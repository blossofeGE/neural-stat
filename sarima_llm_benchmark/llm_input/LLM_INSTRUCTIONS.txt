SARIMA / ARIMA BLIND BENCHMARK — UNIVERSAL INSTRUCTIONS
FULL DATASET MODE — FEATURES_30 / FEATURES_31 / RAW_SERIES

ЦЕЛЬ
Для каждого временного ряда выбрать ровно один наиболее подходящий класс из фиксированного каталога из 42 спецификаций ARIMA/SARIMA. Эти инструкции универсальны: используй их с ОДНИМ из трёх вариантов входного набора за запуск.

1. КАК ОПРЕДЕЛИТЬ ТИП ЭКСПЕРИМЕНТА

Выбери тип по имени и структуре загруженного основного CSV:

A) FEATURES_30
Файл обычно называется blind_test_features_30.csv.
Содержит series_id и 30 диагностических признаков.
Столбец series_id — идентификатор, а не признак.
Признак bic_winner в этом варианте отсутствует и не должен быть придуман.

B) FEATURES_31
Файл обычно называется blind_test_features_31.csv.
Содержит series_id и 31 диагностический признак, включая bic_winner.
В этом варианте bic_winner является частью предоставленного входа и может учитываться как один из признаков. Не интерпретируй его как скрытую метку истинного класса и не подменяй им собственный выбор.
Не путай этот эксперимент с FEATURES_30.

C) RAW_SERIES
Файл обычно называется blind_test_raw_series.csv.
Содержит идентификаторы series_id и исходные наблюдения временных рядов (возможно, в широком или длинном формате).
Определи формат по заголовкам и структуре файла. Не считай series_id, номера временных точек, индексы или служебные поля значениями наблюдений.
Для каждого series_id анализируй значения именно его временного ряда, сохраняя исходный порядок наблюдений. Не объединяй разные ряды.
Feature dictionary для RAW_SERIES не является описанием значений исходного ряда; используй его только если в файле действительно присутствуют соответствующие диагностические признаки.

Если тип входа нельзя надёжно определить или формат данных неоднозначен, не угадывай: сообщи, что именно неясно, и попроси уточнение.

2. ВХОДНЫЕ ФАЙЛЫ

Для каждого запуска пользователь передаёт:
- ровно один основной blind CSV: blind_test_features_30.csv ИЛИ blind_test_features_31.csv ИЛИ blind_test_raw_series.csv;
- class_catalog.csv — каталог допустимых классов, их class_id и названий спецификаций;
- feature_dictionary.csv — словарь диагностических признаков (особенно важен для FEATURES_30 и FEATURES_31; для RAW_SERIES используй при необходимости).

Не используй batch-файлы, если передан полный blind CSV. Обработай весь основной CSV. Если технические ограничения не позволяют надёжно обработать весь файл, прямо сообщи об этом; не заявляй о полном результате, если обработана только часть строк.

3. ПРАВИЛА КЛАССИФИКАЦИИ

- Для каждого входного series_id выбери ровно один predicted_class_id из диапазона 0..41, используя только каталог классов и данные текущего эксперимента.
- Допустимы только классы, перечисленные в class_catalog.csv. Не придумывай классы, названия или ID.
- Не используй внешние источники, скрытые ответы, private evaluation, answer key, test arrays, обучающие метки или сведения, которых нет в разрешённых входных файлах.
- Не пытайся восстановить или угадать истинные метки по порядку строк, имени файла, порядку series_id или структуре каталогов.
- Не пропускай строки, не объединяй разные объекты и не создавай дубликаты.
- predicted_specification должна точно соответствовать выбранному class_id и названию в class_catalog.csv.
- confidence — численная самооценка уверенности от 0 до 1. Это НЕ калиброванная вероятность и не оценка качества на тесте.
- В FEATURES_30 используй только фактически предоставленные 30 признаков.
- В FEATURES_31 используй предоставленные 31 признак, включая bic_winner, но не считай его гарантированно правильным ответом.
- В RAW_SERIES классифицируй по исходной динамике ряда; не утверждай, что использовал диагностические признаки, если они не были предоставлены или вычислены тобой из разрешённых данных.

4. ФОРМАТ ОТВЕТА

Верни CSV-файл (предпочтительно как вложение), строго с четырьмя колонками и именно в таком порядке:

series_id,predicted_class_id,predicted_specification,confidence

Требования:
- ровно одна строка на каждый входной series_id;
- каждый входной series_id присутствует ровно один раз;
- нет лишних series_id и дубликатов;
- predicted_class_id — целое число от 0 до 41 и существует в class_catalog.csv;
- predicted_specification — точное название выбранного класса из class_catalog.csv;
- confidence — конечное числовое значение от 0 до 1;
- не добавляй Markdown, комментарии, пояснения или дополнительные столбцы внутрь CSV;
- сохраняй series_id без изменений.

5. ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА ПЕРЕД ВЫДАЧЕЙ

Перед сохранением результата:
1) Посчитай число строк во входном blind CSV (без заголовка).
2) Сравни полный список входных series_id со списком в результате.
3) Проверь, что нет пропусков, лишних ID и дубликатов.
4) Проверь, что каждый predicted_class_id существует в каталоге, а specification соответствует этому ID.
5) Проверь диапазон confidence [0, 1].
6) Укажи отдельно фактическое число обработанных рядов и результат проверки полноты.

Не ограничивайся примерами, первыми строками или краткой таблицей. Не заявляй, что обработан весь файл, если это не подтверждено проверкой.
